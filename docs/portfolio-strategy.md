# Portfolio Strategy

Carter's portfolio, GitHub, and resume serve different purposes.

## Resume

The resume should be highly curated.

Question:

> Does this increase the likelihood Carter gets this role?

For product-development, embedded, consumer-electronics, robotics, or R&D applications, emphasize projects that show:

- PCB design
- embedded firmware
- electronics
- control systems
- hardware/software integration
- robotics
- debugging
- product development
- testing
- system architecture

For power-oriented applications, emphasize:

- circuits
- power systems
- battery protection
- low-voltage cutoff work
- power electronics
- PCB design
- electrical coursework and labs

## Portfolio

The portfolio can be broader than the resume. It should preserve meaningful technical work, including completed projects, active projects, prototypes, experiments, older projects, software projects, and learning projects.

Strongest engineering projects should be surfaced first.

Recommended hierarchy:

1. Featured engineering projects
2. Embedded, electronics, and robotics archive
3. Software and supporting systems
4. Experiments and work in progress
5. Older/archive work

## GitHub

GitHub should provide technical evidence.

Question:

> Can another engineer see what was actually done?

Repositories should have:

- clear names
- meaningful descriptions
- README files
- project status
- diagrams or photos where useful
- schematics or PCB renders where appropriate
- build/setup instructions
- test results when available
- lessons learned
- future improvements

Not every portfolio project needs a public GitHub repository. Not every GitHub repository needs to be featured.

## Pinned Repositories

Pinned repositories should gradually emphasize engineering:

1. Wall-E Robot
2. AI-Assisted PCB Design / EasyEDA Automation
3. Low-Voltage Cutoff PCB
4. Dual Robotic Arms
5. Another embedded or PCB project
6. One polished supporting software project if useful

Pure web projects should not dominate pinned repositories.

## Engineering Honesty

Use accurate status labels:

- Concept
- Design
- Prototype
- Tested Prototype
- Rev A
- Rev B
- Completed
- Archived

Do not claim hardware was tested unless there is test evidence. Do not claim a PCB was built if it was only designed. Credibility is more important than sounding impressive.
